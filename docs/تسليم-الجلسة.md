# تسليم الجلسة — يُقرأ أول كل جلسة ويُحدَّث آخرها

## الرؤية الثابتة
نموذج صغير مستقل للاستعمال الشخصي، يعمل باستمرار؛ يوجّهه Claude بمهام مكتوبة، ويراجع نتائجه ويختبرها في الجلسة التالية ثم يحمّله المهمة التالية. الجودة قبل الكثرة.

## الآلية
- **الطابور:** ملفات JSON في `tools/builder/tasks/` (id، prompt، tests، expected) في الفرع الرئيسي.
- **العامل:** `tools/builder/worker.py` على Kaggle. يسحب المهام الجديدة كل ١٠ دقائق، يكتب النموذج شيفرة ضاد، ويتحقق منها المحرك الحقيقي (حتى ٣ محاولات).
- **النتائج:** تُدفع إلى الفرع `builder-results` فقط (`results/<id>.json` و`results/done.json`). لا شيء يدخل الفرع الرئيسي إلا بعد مراجعة Claude.
- **المراجعة (دور Claude في أول كل جلسة):** `git fetch origin builder-results` ثم قراءة `results/`؛ المقبول يُنسخ إلى المكتبة مع اختبار، والمرفوض يُسجَّل سببه ويُعاد صياغة مهمته.

## التشغيل (آلي كليًا، دون تدخل من صاحب المشروع)
GitHub Actions (`.github/workflows/builder.yml`) يشغّل نواة على كاجل تلقائيًا: عند دفع مهام جديدة إلى `tools/builder/tasks/` وكل ٦ ساعات. تُجمَع النتائج في `builder-results`. التشغيل اليدوي: `gh api -X POST repos/kaledgmal71-commits/dhad/actions/workflows/builder.yml/dispatches -f ref=main`.
- النموذج الحالي Qwen3-8B بلا وضع التفكير (`enable_thinking=False`)، حتى ٣ محاولات لكل مهمة، وسجل المحاولات محفوظ في `results/<id>.json` (`history`).
- قراءة النتائج: `git fetch -q origin +refs/heads/builder-results:refs/remotes/origin/builder-results`.
